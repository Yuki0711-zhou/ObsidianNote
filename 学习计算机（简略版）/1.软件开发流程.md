# 总览-软件开发的7个阶段

**需求分析-设计-开发-测试-部署-运维-迭代**

***
# 🏗️ 软件开发全流程通俗指南

> **一句话版本**：软件开发就像**盖一栋楼**——先想清楚盖什么（需求），再画图纸（设计），然后施工（开发），验收（测试），交房（上线），物业保修（运维），最后根据住户反馈不断装修升级（迭代）。
>
> 适合人群：计算机小白 / 被老板逼着来学习的打工人 😭

---

## 📋 总览：一张图看懂全流程

```
①需求分析 → ②设计 → ③开发 → ④测试 → ⑤部署上线 → ⑥运维 → ⑦迭代
 (想盖啥)   (画图纸) (施工)  (验收)   (交房)      (物业)  (装修升级)
```

> 💡 **现实中的真相**：公司不会死板地走完一步再走下一步，而是**转着圈循环**（这叫"迭代开发"）。但每个环节该做的事，全世界都大同小异。

---

## ① 需求分析 —— 「想盖什么楼？」

**核心问题：我们到底要做什么？给谁用？解决什么问题？**

### 需要做什么

- **收集需求**：跟客户、老板、用户聊天，把模糊的想法变具体。
  - ❌ 老板说："我要一个外卖 App。"（太模糊！）
  - ✅ 追问后：给谁用？有什么功能？外卖小哥要不要实时定位？付款方式有几种？
- **挖掘真需求**：用户说"想要一匹更快的马"，真需求是"更快到达目的地"。别被表面的说法带偏。
- **排出优先级**：哪些是必须有（P0），哪些是加分项（P1、P2）。

### 具体怎么做

| 方法/工具 | 干什么用 |
|---|---|
| **用户故事** | 写需求的格式："作为【饿了的大学生】，我想要【推荐附近美食】，以便【快速吃上饭】" |
| **竞品分析** | 看看美团、饿了么是怎么做的 |
| **原型图**（Axure / Figma / 墨刀） | 画出页面大概样子（方框+按钮），让老板先"看见"产品 |

### 📦 产出物
**PRD 需求文档 + 原型图**　👷 主要角色：**产品经理（PM）**

> ⚠️ **为什么最重要**：软件项目失败的头号原因就是需求没搞清楚。楼盖到一半再改图纸，代价最大！

---

## ② 设计 —— 「画图纸」

需求定了，技术团队开始设计"怎么实现"。分两层：

### 🏛️ 架构设计（大楼结构设计）

**回答：系统由哪些部分组成？它们怎么协作？**

一个外卖 App 拆开来大概是：

```
用户手机上的 App（前端）──请求──▶ 服务器上的程序（后端）──读写──▶ 数据库
  用户看得见的界面                    处理订单、算钱                 存所有数据
```

要拍板的技术问题：

- **选技术栈**：后端用 Java（稳）/ Python（快）/ Go（并发强）？数据库用 MySQL（存订单）还是 Redis（缓存热销菜）？
- **单体还是微服务**：一个代码包（单体，小项目够用）还是拆成多个小服务（微服务，大厂高并发才需要）？
- **定接口（API）**：前端和后端像"前台和后厨"，要约定好传菜口——前端请求 `GET /api/orders` 就拿到订单列表。

🛠️ 工具：draw.io / ProcessOn 画架构图；**Swagger / Apifox** 写接口文档。

### 🎨 UI/UX 设计（室内装修设计）

- **UI（界面）**：按钮放哪、什么颜色、字体多大（工具：Figma、Sketch）
- **UX（体验）**：下单要几步？能不能 3 步内完成？

### 📦 产出物
**架构文档 + API 接口文档 + UI 设计稿**　👷 角色：**架构师 / 设计师**

---

## ③ 开发 —— 「施工」

程序员真正开始写代码了！

### 前后端分工（最基础的概念）

| 角色 | 干什么 | 常用技术 |
|---|---|---|
| **前端** | 用户看得见摸得着的页面 | HTML / CSS / JavaScript、Vue、React；App 用 Flutter |
| **后端** | 服务器上的逻辑：登录验证、下单扣款 | Java、Python、Go、Node.js |

两者通过 **API** 通信：`前端发请求 → 后端查数据库 → 返回数据 → 前端展示`

### 数据库 = 很多张 Excel 表

```
用户表：  id | 用户名 | 密码 | 手机号
订单表：  订单号 | 用户id | 金额 | 状态
```

用 **SQL 语言**操作：**增（INSERT）、删（DELETE）、改（UPDATE）、查（SELECT）**

### 🌟 Git —— 多人协作的命根子

- 代码放"仓库"里，每次改动都记录，改错了能回滚（超级加强版 Word 修订模式）
- 流程：从主干拉分支写代码 → 提交 **Pull Request** 请同事审查 → 合并回主干
- 平台：**GitHub / GitLab / Gitee**

### 📦 产出物
**能跑的代码**　👷 角色：**前端 / 后端工程师**

---

## ④ 测试 —— 「验收」

代码写完 ≠ 能用。测试就是**想尽办法把软件搞坏，看它扛不扛得住**。

### 测试的种类（由小到大）

| 类型 | 通俗解释 | 举例 |
|---|---|---|
| **单元测试** | 测每一个小零件 | 输入 3 公里，配送费函数应输出 5 块 |
| **集成测试** | 零件拼起来测 | 选菜→下单→扣款→生成订单，整条链对不对 |
| **系统测试** | 对照需求整体测 | 拿着 PRD 把每个功能点一遍 |
| **验收测试** | 客户亲自验收 | "我要的功能都有了吗？" |

### 常见测试手段

- **自动化测试**：把"点击-检查"写成脚本自动跑（Selenium、pytest、JUnit）
- **性能测试**：1 万人同时下单会不会崩？（JMeter）
- **安全测试**：黑客能不能偷到密码？（SQL 注入、XSS）

### 🐞 发现 Bug 怎么办？

提 **Bug 单**（"在 XX 页面点 XX，预期 XX，实际 XX，复现步骤如下"）→ 开发修复 → 测试验证 → 关闭

### 📦 产出物
**Bug 清零 + 测试报告**　👷 角色：**测试工程师（QA）**

---

## ⑤ 部署上线 —— 「交房」

把软件放到真实环境，让用户真正用起来。

### 基本步骤

1. **租服务器**：在**阿里云 / 腾讯云 / AWS** 上租机器——软件"住"的地方
2. **打包构建**：把源代码编译压缩成可直接运行的程序
3. **配置环境**：服务器上装数据库、运行环境等
4. **发布启动**：用户就能访问了！🎉

### 🚀 现代公司的进阶玩法

| 概念 | 一句话解释 |
|---|---|
| **CI/CD** | 代码一合并，自动"编译→测试→部署"的流水线（Jenkins、GitHub Actions） |
| **Docker 容器** | 把程序+环境打包成"集装箱"，一次打包到处运行 |
| **灰度发布** | 新版本先给 5% 用户试用，没问题再全量，出事秒回滚 |

### 📦 产出物
**线上能访问的产品**　👷 角色：**运维（DevOps）**

---

## ⑥ 运维 —— 「物业 + 保修」

上线不是结束，服务才刚刚开始。

### 日常要做的事

- **监控报警**：24 小时盯着——CPU 满了？接口变慢了？工具：**Prometheus + Grafana**，出事自动打电话把工程师叫醒 📞
- **查日志**：用户报"下单失败"，像侦探一样翻日志（log）找线索
- **扛住突发**：双十一流量暴增 → 临时加服务器（弹性扩容）；被攻击 → 限流、防火墙
- **数据备份**：每天备份数据库，防止误删库后欲哭无泪

---

## ⑦ 迭代 —— 「装修升级」

根据用户反馈和数据，持续改进：

```
收集反馈（评价 + 埋点统计"多少人在下单页放弃了"）
   → 排优先级（下版本做什么？）
   → 回到①需求分析 → ②设计 → ③开发 → …… 循环往复 ♻️
```

这就是为什么叫软件**生命周期**——它永远活着，一直在变。

## 🗂️ 全流程速查表

| 阶段 | 一句话概括 | 核心产出 | 主要角色 |
|---|---|---|---|
| ① 需求分析 | 想清楚做什么 | PRD、原型图 | 产品经理 |
| ② 设计 | 想清楚怎么做 | 架构图、接口文档、UI 稿 | 架构师、设计师 |
| ③ 开发 | 写代码实现 | 可运行的程序 | 前端/后端工程师 |
| ④ 测试 | 想尽办法搞坏它 | 测试报告 | 测试工程师 |
| ⑤ 部署 | 放到线上让用户用 | 线上系统 | 运维/DevOps |
| ⑥ 运维 | 盯着它别出事 | 稳定性保障 | 运维工程师 |
| ⑦ 迭代 | 根据反馈持续改进 | 新版本 | 全员 |

## 🎓 给小白的上手路线

1. **先学一门语言**：Python（最友好）或 JavaScript
2. **学 Git**：半天入门，终身受益
3. **做个迷你项目**："待办清单"——自己走一遍 `写代码 → 本地跑 → 传 GitHub → 部署上网` 的全流程
4. **回头再看本文**：每个环节都会豁然开朗："哦，原来如此！"

---

> 🌟 **全文核心思想**：每一步都是为了**减少返工风险**——前面的环节越严谨，后面救火越少。需求阶段的 1 小时，可能省去开发阶段的 100 小时。
