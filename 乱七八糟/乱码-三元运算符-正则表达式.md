## 1️⃣ 中文乱码：为什么只有中文变成"娴嬭瘯"？

### 🎬 案发现场还原

写的代码注释：

```csharp
// 这是测试代码
```

保存关掉再打开，变成：

```csharp
// 杩欐槸娴嬭瘯浠ｇ爜
```

英文和代码本身好好的，**只有中文烂了**。

### 🔍 根本原因：字符编码不一致

计算机存文字的本质是：**把每个字符存成一个数字编号**。但"把汉字翻译成数字"这件事，世界上有好几套标准：

| 编码标准 | 出身 | 特点 |
|---|---|---|
| **ASCII** | 美国 | 只有英文字母、数字、符号（128 个），**没有中文** |
| **GBK / GB2312** | 中国国标 | 英文 1 个字节，中文 2 个字节（Windows 中文版默认） |
| **UTF-8** | 国际通用 | 英文 1 个字节，中文 3 个字节，**全世界通行** |

**乱码原理一句话**：

> 保存时用一套编码（如 GBK），打开时按另一套解码（如 UTF-8）——同一个中文字，两套标准编号不同，按错的规则还原，就成了鬼画符。

类比：你用**摩斯电码**发消息，朋友拿**旗语手册**解码——必然是乱码。

### 🕵️ 案情推断

```
敲代码的工具（编辑器 A）保存时 → 用了 GBK
再次打开的工具（编辑器 B）   → 按 UTF-8 解读
结果：中文全灭，英文没事
```

为什么英文没事？ASCII、GBK、UTF-8 对**英文字母的编号完全一致**，只有中文编号规则不同——所以乱码永远只咬中文。

### 🛡️ 如何避免

**① 统一使用 UTF-8 编码（最重要！）**

编辑器设置里把默认编码改成 UTF-8，团队所有人统一。VS Code、Visual Studio、Rider 都支持，看窗口右下角编码标识。

**② C# 项目里加保险（防控制台乱码）**

```csharp
// 程序开头加这一行，让控制台也用 UTF-8 输出
Console.OutputEncoding = System.Text.Encoding.UTF8;
Console.WriteLine("你好世界");  // 不然可能输出"浣犲ソ涓栫晫"😂
```

**③ 读写文件时显式指定编码**

```csharp
// 不指定的话 .NET 会按系统默认编码（中文 Windows 是 GBK）猜
File.ReadAllText("test.txt", Encoding.UTF8);   // 显式声明，别让它猜！
File.WriteAllText("test.txt", "中文内容", Encoding.UTF8);
```

**④ 团队约定**

README 或团队规范里写死："**所有源文件统一 UTF-8 编码**"，从根源杜绝 90% 的乱码。

> 💡 抢救已乱码的文件：用编辑器"以 GBK 编码重新打开"→ 看到正常中文 → "另存为 UTF-8"，救回来了。

### 📝 标准答案

> 根因是字符编码不一致——保存和打开时用了两套标准（常见 GBK 存、UTF-8 读）。三套编码对英文字母编号一致所以英文不乱，中文编号规则不同所以只有中文乱码。避免方法：编辑器统一 UTF-8；C# 加 `Console.OutputEncoding = Encoding.UTF8;`；读写文件显式指定 `Encoding.UTF8`；团队约定统一编码。

## 2️⃣ 三元运算符：一行写完 if-else

### 📖 是什么

**三元运算符 = 简化版的 if-else**，由 3 个部分组成：

```
条件 ? 条件为真时的值 : 条件为假时的值
 ↑        ↑                ↑
 第1部分    第2部分（真）     第3部分（假）
```

C# 和 JavaScript 语法一模一样：

```csharp
条件表达式 ? 结果A : 结果B
```

### 🆚 对比感受

**场景：根据分数判断及格与否**

普通 if-else（5 行）：

```csharp
string result;
if (score >= 60) {
    result = "及格";
} else {
    result = "不及格";
}
```

三元运算符（1 行）：

```csharp
string result = (score >= 60) ? "及格" : "不及格";
```

**拆解**：

```
(score >= 60)  ?  "及格"  :  "不及格"
     ↑           ↑           ↑
  条件：够60吗？  真：及格    假：不及格
```

读法：**"分数大于等于 60 吗？是就取'及格'，否则取'不及格'"**

### 🛠️ 典型使用场景

| 场景 | 例子 |
|---|---|
| 简单赋值二选一 | `string level = age >= 18 ? "成年" : "未成年";` |
| 数字取最大/最小 | `int max = a > b ? a : b;` |
| 页面显示文案 | `label.Text = isVip ? "尊贵的会员" : "普通用户";` |
| 函数返回值 | `return count > 0 ? count : 0;`（负数归零） |

### ⚠️ 什么时候别用

三元只适合**简单的二选一**。嵌套强行三元 = 代码审查挨骂重灾区：

```csharp
// ❌ 禁止这样写！
string s = a > 0 ? (b > 0 ? "都正" : "a正b负") : (b > 0 ? "a负b正" : "都负");
// 老老实实 if-else，同事会感谢你的
```

口诀：**一行能写完的二选一用三元，超过一行就老老实实 if-else**。

### 📝 标准答案

> 格式 `条件 ? 真时的值 : 假时的值`，是 if-else 的一行简化版，适合简单二选一赋值（如 `string r = score >= 60 ? "及格" : "不及格";`）。嵌套复杂逻辑时不要强行使用，保持 if-else 的可读性。

## 3️⃣ 正则表达式：文本匹配的神器

### 📖 是什么

**正则表达式（Regular Expression，简称 regex）= 一种描述"文本长什么样"的公式**，用来**查找、匹配、替换、校验**文本。

一句话：它是给文本下的"通缉令"——"我要找所有长得像 `xxx@xxx.com` 的字符串"。

### 🎯 为什么需要它

老板让你检查 10 万个用户的邮箱格式。总不能逐个肉眼看吧？正则一行解决：

```csharp
string pattern = @"^\w+@\w+\.\w+$";
bool isEmail = Regex.IsMatch(userInput, pattern);
```

### 🔤 核心语法（记这几个就够入门）

**普通字符 + 特殊符号（通配符）**的组合：

| 符号 | 意思 | 例子 |
|---|---|---|
| `.` | 任意一个字符 | `a.c` 匹配 "abc"、"a1c"、"a$c" |
| `\d` | 一个数字 | `\d\d\d` 匹配任意三位数 |
| `\w` | 一个字母/数字/下划线 | `\w+` 匹配单词 |
| `+` | 前面重复 **1 次或多次** | `\d+` 匹配任意长度数字 |
| `*` | 前面重复 **0 次或多次** | `ab*c` 匹配 "ac"、"abbbc" |
| `?` | 前面**有或没有**（0 或 1 次） | `colou?r` 匹配 "color" 和 "colour" |
| `{n}` | 正好重复 n 次 | `\d{11}` 匹配 11 位数字 |
| `^` | 开头 | `^abc` 以 abc 开头 |
| `$` | 结尾 | `abc$` 以 abc 结尾 |
| `[...]` | 括号里任选其一 | `[abc]` 匹配 a/b/c；`[0-9]` 等于 `\d` |
| `|` | 或者 | `cat|dog` 匹配 cat 或 dog |

### 🧪 实战例子（由浅入深）

**例 1：验证手机号（11 位数字）**

```csharp
string pattern = @"^1\d{10}$";
// 读法：开头是 1，后面正好 10 个数字，然后结束
Regex.IsMatch("13812345678", pattern)  // true ✅
Regex.IsMatch("12345", pattern)        // false ❌
```

**例 2：提取字符串里所有的数字**

```csharp
string text = "价格是25元，库存100件";
MatchCollection matches = Regex.Matches(text, @"\d+");
// 结果："25" 和 "100"
```

**例 3：替换敏感词**

```csharp
string comment = "你这个笨蛋";
string cleaned = Regex.Replace(comment, "笨蛋", "**");
// 结果："你这个**"
```

### 🛠️ 使用场景（无处不在）

| 场景 | 例子 |
|---|---|
| 表单验证 | 手机号、邮箱、身份证号、密码强度 |
| 日志分析 | 几万行日志里抓出所有 IP 地址、错误行 |
| 数据清洗 | 批量替换、删除、提取特定格式文本 |
| 编辑器 | VS Code 查找替换支持正则（勾选 `.*` 图标） |
| 爬虫 | 从网页 HTML 里提取数据 |

### ⚠️ 注意事项

1. **正则难读是公认的**——如 `^(?=.*[A-Z])(?=.*\d).{8,}$`（密码强度校验），初学看不懂很正常，查文档、用在线工具调试即可。
2. 推荐工具：**regex101.com**（在线调试，边写边看匹配结果，神器）。
3. 正则不是万能药：解析 HTML/JSON 等结构化文本，用专门的解析器，别硬上正则（会写出噩梦）。

### 📝 标准答案

> 正则表达式是描述文本模式的公式，由普通字符和通配符（`\d` 数字、`.` 任意字符、`+` 重复一次以上、`{n}` 正好 n 次、`^$` 首尾等）组成。用于查找、匹配、替换、校验文本，典型场景是表单验证（手机号 `^1\d{10}$`）、日志分析、数据清洗。可用 regex101.com 在线调试。
